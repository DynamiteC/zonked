# Browser matrix

Three engines (Chromium, Firefox, WebKit) at three viewports (1280x800 desktop, 390x844 iPhone-like, 412x915 Android-like), 18 checks each, 162 checks in total. Run it with:

```bash
node web/scripts/browser-matrix.mjs
```

The script builds HEAD in a throwaway git worktree under the system temp dir, serves it with `vite preview`, runs every check, removes the worktree and exits non-zero on any failure. It writes `.work/matrix/results.json`, `.work/matrix/matrix.log` and failure screenshots to `.work/matrix/shots/`. It refreshes only the block between the two marker comments below. Set `MATRIX_ONLY=firefox` or `MATRIX_ONLY=chromium:phone-ios` to run a subset.

Engine builds are the ones Playwright installs. They are test builds, not the shipping browsers. The iPhone-like and Android-like runs set viewport, touch and (Chromium and WebKit only) the mobile flag. They do not change the engine, the user agent hardware or the audio stack. Firefox has no mobile emulation in Playwright, so it gets touch only. Firefox runs with its content sandbox off, because it crashes on the test Mac otherwise. That points to the test host, not the app.

Result: 162 of 162 pass. Chromium 54 of 54, WebKit 54 of 54, Firefox 54 of 54. The check "nature loop decodes and plays (MP3)" accepts two paths. Path 1: the MP3 decodes, the sound plays and the message line is empty. Path 2: the decode times out after 8 s, the made-in-code sound plays (engine running, peak above 0) and the fallback note is shown. A hang with no sound (engine not running or peak 0) still fails. Chromium and WebKit took path 1 in all 6 runs. Firefox took path 2 in all 3 runs, shown as "pass (fallback)" in the table.

The Playwright Firefox build may lack MP3 decoding. A real Firefox needs one manual check (owner test list): tap Rain and see whether the recording plays or the fallback note appears.

## Failure analysis

No check fails in the last run. Two earlier problems are fixed. Line numbers in older notes are gone, so search the code for the quoted text.

### 1. No AudioWorklet (fixed, was 9 failures)

The engine goes to state `error` when `AudioWorklet` is missing. The Calm status line now shows a plain message about the browser instead of only "Stopped." All 9 runs pass the check "fallback: no AudioWorklet".

### 2. Firefox Rain loop (fixed, was 3 failures)

In the Playwright Firefox build, `decodeAudioData` never settles on the MP3 loops. The app now races the decode against an 8 s timer. It then plays the closest made-in-code sound and shows a one-line note. The check accepts that path on purpose and records it as "pass (fallback)". Not settled: whether a release Firefox decodes the MP3. Run `MATRIX_ONLY=firefox node web/scripts/browser-matrix.mjs` against a release Firefox, or do the manual check above.
